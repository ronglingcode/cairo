# T21 — Small predicates with source evidence

The pure evaluator supports finite scalar comparisons, small AND/OR groups, selected-account position quantity/average cost, timestamped reported broker marks, actual fills for a named order/symbol/time window, and scoped trader confirmations. Each result includes satisfied/pending/invalid/unknown state and source evidence. Evidence eligibility never grants order approval. It evaluates no generated code and creates no orders or rule state.

The grammar is bounded to 64 nodes, depth eight and 16 children per group. Unknown fields and invalid clauses are rejected even within OR. A known satisfied OR branch can satisfy the group while retaining unknown evidence for the other branch. Broker conditions require connected facts and source times at most 60 seconds old. Broker marks are reported snapshots, not crossing evidence. Missing position/account, stale facts, malformed fills, conflicting duplicates and incomplete relevant coverage do not become true.

REST close comparisons are available only with explicit `historical-context` purpose and are never action eligible. Refreshing bars cannot make a live condition true. Bookmap and live-price predicates remain unknown. Scoped human confirmations require this runtime, account/position/symbol, attachment, interpretation revision, condition and broker facts revision; they expire within five minutes. The caller supplies the reviewed interpretation scope; attachment activation/management remains T22/T26/T27.

Checks: six focused cases cover finite/bounded grammar and purity, broker freshness/scope/marks, snapshot versus historical chart use, groups, mismatched/expired/restarted human confirmations, actual fills versus accepted orders, deduplication/conflicts, and fills usable despite a stale chart. All 60 repository tests, TypeScript and production build passed. No real broker mutation or paid inference. Supported interpretations and active monitoring follow in later tasks.
